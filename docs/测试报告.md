## 测试方法

运行 Node 内置 test runner 执行保存、迁移、数据校验与 Combo 单元测试。浏览器采用 Playwright + Chromium，加载实际 `dist/` 文件。

由于测试环境不允许浏览器直接导航本地服务，本次通过 Playwright 路由从磁盘交付构建文件，不接外网。只为测试打开 debug 标志，不改规则、碰撞、地图或胜利判定。使用 Phaser 的正常游戏更新/物理步进；大量帧使用 headlessStep 跳过绘制，必要处再绘制检查。

这一路径不提供普通网站来源下的 localStorage。因此持久存储由 Node 存储模拟对象单独验证，浏览器中验证的是内存降级及完整游戏流程；发布域名下的跨刷新持久性仍需部署后复核。

## 照片挑战

两角色分别在九个摄影入口建立起始位置，然后通过实际水平控制与跳跃完成。气球遵守实际碰撞和弹射；木马遵守移动平台位置，最后一跳依赖真正 Perfect 判定；开关与星点通过实际接触激活。

18 个案例都达成当次运行的 `runPhotos` 状态，不能用“存档中已经有这张照片”代替本次完成。两角色的局部挑战均无重试通过。

测试仅证明九条摄影局部路线可完成，不等于已经证明“同一局全部 20 小幸福 + 3 照片 + 无伤 + 心流徽章”的完整最优路径。

## 物理与生命周期

水平平台载人 5 秒，角色相对平台的偏移变化为 0px。竖直平台载人 5 秒，最大脚底与台顶偏差约 1.09px，站立过程中没有产生重复 Perfect。

单次精准落台只产生一次 Perfect，继续站立不刷判定。暂停期间模拟时间、Combo 剩余时间、角色位置保持不变。心情耗尽回到检查点、恢复三心，计时继续；无敌结束 alpha 恢复 1。

14 项边界回归覆盖：双指输入与独立释放；canvas 外全局释放/取消；失焦清空与 Esc 恢复；单向平台自下穿过、自上落稳；风区离开恢复重力；星桥到期重开；脚下星桥的 300ms 宽限；照片超时不扣心并重新进入；地图配置 2 点伤害与击退；30/20 模拟更新率落台；布布和一二的空中跳次数；12 次重开无场景输入监听累加；竖屏提示与暂停。

30/20 更新率案例是逻辑测试，不是某款低端手机能保持 30/20 FPS 的性能承诺。

## 视觉检查

检查封面、选角色、城市地形、公交照片区、气球接力、星桥、暂停、设置、结算、路线图、相册、九照片特别封面和竖屏提示。

截图中的既有进度、结算分数和镜头位置包含明确的视觉测试夹具，不把这些截图用作正常游玩成绩的证据。初始发行包不包含这些预设成就或用户存档。

## 已发现并修复

1. 平台换向时极短暂接触变化曾导致重复落地/Perfect：加入真正空中行程门槛，更新测试后通过。
2. 空中五事件入口弹簧最初弹得过高：降低专属入口冲量，实际气球链重测通过。
3. 摄影入口从下方靠近时可能提前触发：缩小脚底触发容差。
4. 触控系统取消时仍可能残留未消费跳跃：取消拥有该指针的跳跃队列。
5. 设置/结算部分文字布局过密：重新布置按钮和结果底部留白，并复查截图。

## 尚未完成的外部验收

```bash
npm run build

python tests/browser_routes.py
python tests/browser_challenges.py
python tests/browser_physics.py
python tests/browser_regression.py
python tests/browser_visual.py
```

浏览器脚本需要 Python 的 Playwright 和 Chromium；这只是 QA 依赖，普通试玩/构建不需要安装。脚本通过 `CHROMIUM_PATH` 环境变量可指定浏览器路径；未设置时使用 `/usr/bin/chromium`。
