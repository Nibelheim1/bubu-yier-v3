# 《布布一二：去见你的小幸福》H5 小游戏 V2 完整改版设计文档

**文档版本：V2.0 设计基线**  
**适用项目：当前 TapTap 上传包 / Phaser 3 + Tiled H5 横版平台游戏**  
**目标：在保留现有美术气质、角色与基础操作的前提下，把“能玩”升级为“有节奏、有选择、有复玩动力、可持续扩展”的完整小游戏。**

---

## 0. 执行摘要

当前项目已经具备一款完整小游戏的骨架：标题页、角色选择、三关、检查点、生命、收集、照片、移动平台、弹簧、相册、存档、移动端按键与结算都已存在。真正的问题并不是“功能少”，而是**功能之间没有形成相互驱动的玩法循环**。

当前核心体验接近：

> 向右移动 → 跳过地形 → 顺路拾取 → 碰障碍回检查点 → 到终点。

V2 不建议增加战斗、装备、技能树、复杂货币或 Roguelike。改版方向确定为：

> **轻跑酷 + 路线选择 + 幸福连击 + 精准落地 + 主题机关 + 照片挑战。**

玩家仍然只需要“左 / 右 / 跳”三类操作，但每 3–8 秒都应该出现一次可感知的判断或反馈：该走安全路还是奖励路、要不要冲 Perfect、能不能维持 Combo、是否挑战隐藏照片、是否利用当前机关走出更漂亮的路线。

V2 的核心成功标准不是“内容更多”，而是：

1. 仅凭移动和跳跃就能产生节奏与爽感；
2. 三关在玩法上明显不同，而不是换皮；
3. 布布与一二形成两种可感知的游玩风格，但都能完成全部主线路径；
4. 第一次通关后，玩家仍有明确理由再玩：照片、徽章、连击、角色差异、个人纪录；
5. 现有 Tiled 配置真正成为数据驱动系统，不再出现“地图里写了机制、游戏里只是弹一句话”的情况。

# 1. 当前版本审计

## 1.1 已确认的技术与内容现状

| 项目 | 当前实现 |
|---|---|
| 引擎 | Phaser 3，Arcade Physics |
| 画面基准 | 960 × 540，16:9，FIT 缩放 |
| 世界重力 | Y = 1150 px/s² |
| 地图 | Tiled JSON，48 × 48 tile |
| 三关尺寸 | 均为 120 × 12 tile，即 5760 × 576 px |
| 角色 | 布布 / 一二 |
| 布布参数 | speed 220；jump -510；coyote 190ms；无二段跳；受伤恢复 1450ms |
| 一二参数 | speed 245；jump -520；coyote 120ms；1 次空中跳；受伤恢复 1050ms |
| 每关内容 | 20 个小幸福、3 张照片、2 个检查点、1 个终点 |
| 存档 | localStorage，v1 |
| 方向控制 | 键盘 + 屏幕左右键 |
| 跳跃 | Jump Buffer + Coyote Time + 可变跳高 |
| 屏幕方向 | 竖屏显示“请把手机横过来” |

现有基础移动本身并不差：有 jump buffer、coyote time、松键截断跳跃、摄像机前置偏移，这些都应该保留。V2 的重点不是推翻手感，而是围绕现有手感建立玩法层。

## 1.2 三关同质化是第一结构性问题

对三张 Tiled 地图逐格比较后：

- 远景图层：100% 相同；
- 近景图层：100% 相同；
- 前景图层：100% 相同；
- 地形碰撞层：不同关之间约 **96.9%–97.2% 相同**；
- 单向平台层：约 **96.0%–96.5% 相同**。

因此当前三关虽然名字、美术主题和对象名称不同，实际移动轨迹高度相似。玩家很快会发现第二、第三关只是“同一条路换颜色”。

**V2 要求：三关不能继续共用同一套地形骨架。**

## 1.3 “地图配置存在、运行时不执行”的问题

当前 Tiled 中已经有不少设计意图，但运行时代码没有真正读取或执行，主要包括：

- `interactionKind`：未用于分派机制，所有 interaction 都只是弹 Toast；
- `once`：未读取，所有 interaction 实际都只触发一次；
- `damage`：未读取，所有伤害固定扣 1 心；
- `resetToCheckpoint`：未读取；
- `pingPong`：移动平台固定 yoyo；
- `collectible value`：未读取；
- `reachableBy`：未读取；
- `cameraBounds` 中的相机参数：未读取；
- `respawnFacing`：未读取；
- 地图内 `goal.nextLevel`：未作为实际流程依据；
- `expectedMinutes`：仅为元数据，没有任何关卡节奏约束。

这意味着当前项目表面上是“数据驱动”，实际上仍高度硬编码。V2 必须先修这一层，否则每新增一个机关都会继续扩大隐性 bug。

## 1.4 当前可确认 / 高风险 Bug 清单

### P0：改玩法前必须处理

| 编号 | 问题 | 当前风险 | V2 处理 |
|---|---|---|---|
| P0-01 | 移动平台由 Tween 改位置，body `moves=false`，再手动 `updateFromGameObject()` | 玩家可能无法稳定被平台带动，垂直平台抖动/滑落 | 改为正确的 Arcade moving body；优先使用物理速度驱动，或 Tween + `directControl` + friction |
| P0-02 | 触屏控制只处理 object `pointerup / pointerout` | 手指在 canvas 外松开、系统取消触摸时可能出现“松手仍移动” | 全局监听 `pointerupoutside`、`gameout`、页面失焦、visibilitychange，统一 `releaseAll()` |
| P0-03 | interaction 的 `once:false` 无效 | 第三关 windZone 写着可持续触发，实际首次触发后永不执行 | 让 trigger manager 按 `once`、cooldown、enter/leave 处理 |
| P0-04 | 小幸福存档只保存“历史最高数量” | 玩家换路线收不同物件仍只是数字 max；语义模糊 | V2 明确“小幸福=单局表现”，显示“本次/最高”；照片才是永久收集 |
| P0-05 | 受伤后的透明动画存在结束时仍为低 alpha 的风险 | 角色可能恢复后仍半透明 | 受伤闪烁单独实现，结束强制 `alpha=1`、`clearTint()` |
| P0-06 | 单向平台碰撞只用当前 bottom 与 tileY 判断 | 高速下落、移动平台附近可能穿透/卡边 | 使用 previous bottom + descending 条件，增加容差与落台状态测试 |

### P1：系统化重构时修复

- HUD 把 `/20`、`/3` 写死，应读取 manifest；
- hazard 的 damage / reset 配置必须生效；
- `reachableBy` 若保留则必须执行，否则删除此字段；
- 移动平台的 axis / distance / duration / pingPong 都应统一走数据；
- checkpoint 的 order、facing、回血逻辑要显式；
- 所有 Scene 级 input listener 在 shutdown 时严格注销；
- 不允许关键机制只通过字符串 `interactionKind` 后又退化成 Toast。

## 1.5 当前设计层面的关键问题

1. **低决策密度**：绝大多数时间玩家只是在向右走。
2. **低反馈密度**：收集物与照片只有一次性音效，没有形成连续节奏。
3. **障碍同质**：不同名字最终只是“矩形伤害区”。
4. **角色不平衡**：一二同时拥有更高速度、更高跳跃和二段跳，优势过于直接；布布的 coyote / invulnerability 优势不够可感知。
5. **照片缺乏成就感**：当前照片只是碰一下即可获得。
6. **关卡目标和体量不匹配**：地图属性写 3–5 分钟，但 5760px 在 220–245px/s 基础速度下，纯水平移动只有约二十多秒量级。
7. **检查点与失败逻辑不统一**：有检查点，但心清空后仍整关 restart，会削弱检查点价值。

# 2. V2 产品定位与设计原则

## 2.1 一句话定位

> **一款操作极简、节奏轻快，以“去见你”为情绪线索的横版轻跑酷游戏；玩家通过漂亮地跳、选路线、连幸福、拍照片，把一段普通路程玩成自己的小冒险。**

## 2.2 六条设计支柱

### 支柱 A：不增加操作按钮

主玩法保持：

- 左；
- 右；
- 跳。

所有新机制尽量通过“位置、时机、落点、路径”表达，而不是增加攻击、冲刺、技能键。

### 支柱 B：低门槛，高上限

主线路径确保普通玩家能通关；高收益路线、Perfect、Combo、照片挑战承担高手空间。

### 支柱 C：每 3–8 秒有一次有效反馈

有效反馈可以是：

- 收到小幸福；
- Perfect 落地；
- Combo 里程碑；
- 弹簧 / 气球连续弹跳；
- 路线分叉；
- 机关状态变化；
- 拍到照片；
- 检查点；
- 主题演出。

### 支柱 D：三关三种“动词组合”

- 第一关：跑 + 观察交通节奏 + 借物前进；
- 第二关：弹 + 空中接力 + 动态平台；
- 第三关：点亮 + 限时星桥 + 风与光。

### 支柱 E：惩罚轻，精通深

失败主要损失：Combo、无伤徽章、个人纪录；不要频繁把玩家整段打回去。

### 支柱 F：角色是“风格差异”，不是“强弱差异”

一二更灵活；布布更稳定、更容易 Perfect。两者都能完成全部主线、全部照片挑战，但最优路径和手感不同。

# 3. V2 核心循环

## 3.1 3–8 秒微循环

> 看前方 → 判断安全 / 奖励路线 → 起跳 → 收幸福 / 踩机关 → 落地判定 → 获得反馈 → 立刻看到下一目标。

关键要求：任何直线空跑超过约 3 秒，都应有明确视觉目标。

## 3.2 单关循环

> 起步教学 → 第一轮流畅挑战 → 路线分叉 → 照片小挑战 → 检查点 → 新机制升级 → 复合挑战 → 情绪收束 → 结算。

目标时长建议：

- 初次通关：约 90–150 秒；
- 熟练通关：约 55–90 秒；
- 照片 / 高 Combo 全收集跑：通常略高于熟练通关。

不再以“3–5 分钟硬拖时长”为目标。

## 3.3 长期循环

> 通关三关 → 补照片 → 补三类徽章 → 换角色挑战 → 刷个人纪录 → 解锁纪念卡 / 合影 → V2.1 无限模式。

# 4. 核心系统设计

## 4.1 移动手感基线

现有重力 1150、jump buffer、coyote time、松键截断跳跃均保留。V2 不宜大幅改变纵向手感，避免“玩法还没做完先把控制改坏”。

### 推荐基准参数

| 参数 | 布布 | 一二 |
|---|---:|---:|
| 基础速度 | 230 | 230 |
| 基础跳跃 | -515 | -505 |
| Coyote Time | 180ms | 130ms |
| Jump Buffer | 150ms | 150ms |
| 空中额外跳跃 | 0 | 1 |
| 二段跳力度 | — | 基础跳跃 × 0.92 |
| 默认受伤无敌 | 900ms | 900ms |

**原则：移除“一二天然跑得更快”的优势。** 角色差异由机制而不是纯速度决定。

## 4.2 幸福 Combo：V2 的主节奏系统

### 目标

把“小幸福”从普通收集物升级为：

1. 路线引导；
2. 节奏计时器；
3. 玩家表现反馈；
4. 复玩目标。

### 规则

- 拾取“小幸福” → Combo +1，并重置 Combo 计时；
- 命中 Perfect 落点 → Combo +1；
- 完成指定连续机关动作 → Combo +1；
- Combo 基础保持时间：3.2 秒；
- 布布因“稳定”特性，Combo 保持时间建议 3.8 秒；
- 受伤 / 掉落 / 超时 → Combo 归零；
- 普通落地不会主动清 Combo；
- 暂停、系统切后台期间冻结 Combo 计时。

### 反馈等级

| Combo | 反馈 |
|---:|---|
| 1–4 | 普通收集音效 / 小粒子 |
| 5 | UI 第一次弹出“幸福连击 ×5” |
| 10 | 收集音调升级、角色尾迹出现 |
| 15 | 星星粒子增强、UI 轻微脉冲 |
| 20+ | 进入“心流”表现：更完整尾迹与特殊音阶，但不提高基础移速，避免破坏地图 |

不建议把 Campaign 做成满屏分数。主 HUD 只显示：

> `小幸福 12/20   Combo ×9`

结算保存：最高 Combo。

## 4.3 Perfect Landing：提升跳跃上限的核心机制

### 判定方式

不是每个平台都判 Perfect。由 Tiled `perfectZones` 对象层标出“值得精准落地”的平台。

- 玩家从上方落下；
- 首次接触平台时检测玩家中心 X；
- 处于指定中心区域则 Perfect；
- 同一落点一次空中流程只判一次。

### 推荐判定宽度

- 一二：平台宽度约 30%–32%；
- 布布：平台宽度约 42%–46%；
- 移动平台：统一增加约 8% 容错。

### Perfect 反馈

- `PERFECT!` 文字 350–450ms；
- 平台轻微 squash / 星星爆开；
- 音效升调；
- Combo +1；
- 摄像机极轻微冲击，禁止大幅晃动；
- 连续 Perfect 达到 3 / 5 时增加额外庆祝反馈。

**不建议使用真实全局慢动作作为常态反馈**，移动端更容易造成输入和物理不一致；优先用视觉缩放、粒子和声音完成“打击感”。

## 4.4 路线选择

每个关卡至少出现 4 次明显路线选择。

### 基础结构

**安全路**：

- 更宽平台；
- 少动态机关；
- 不要求连续跳；
- 奖励少。

**奖励路**：

- 更高 / 更快 / 更依赖精准落点；
- 有 1–2 个额外小幸福；
- 有 Perfect 区或照片入口。

### 规则

1. 分叉后 1–2 个屏幕内必须重新汇合；
2. 不允许因为选择安全路进入死路；
3. 奖励路失败时尽量掉回安全路，而不是直接死亡；
4. 路线选择通过小幸福轨迹、光线、平台高度表达，不弹“请选择 A/B”；
5. 布布与一二主线路径都可达；角色专属捷径只能影响效率，不影响完整收集。

## 4.5 生命、受伤与失败

当前“碰任何 hazard → 扣心 → 立即回检查点”的处理过于同质。

### V2 分为三类

#### A. 软干扰

不扣心，只影响移动或 Combo：

- 水洼：减速；
- 夜露：滑动；
- 泡泡池：强制弹起；
- 逆向传送带：改变水平速度。

#### B. 普通伤害

- 扣 1 心；
- Combo 清零；
- 小幅击退；
- 不立刻回检查点。

例如：滑板侧撞、软锤、荆棘。

#### C. 掉落 / 致命区域

- 扣 1 心；
- 回最近检查点；
- 短暂无敌。

### 心情清空

不再整关 restart。

建议：

> 回最近检查点，恢复 3 心，但本局“无伤徽章”失效，个人计时继续。

这样既保留失败代价，也不打断休闲体验。

## 4.6 照片从“碰一下”改为 5–15 秒小挑战

每张照片都应有：

1. 清晰入口；
2. 一个独立机制；
3. 成功瞬间；
4. 可立即重试；
5. 不影响主线通关。

挑战失败只重置挑战，不伤血、不把玩家送回检查点。

### 统一流程

> 进入挑战 Trigger → UI 小提示 → 激活临时对象 → 玩家完成条件 → 咔嚓演出 → 永久解锁照片。

照片一旦获得，后续重玩仍可触发演出，但不会重复写存档。

## 4.7 两名角色重做

### 布布：地面节奏 / 稳定型

被动 **「稳稳落地」**：

- Perfect 区域明显更宽；
- Combo 宽限 +0.6 秒；
- 连续 Perfect 3 次时获得短暂视觉冲刺感（只做表现或极小速度增益，不超过 8%，持续 <0.6 秒）。

玩家感受：

> “我没有二段跳，但很容易一路稳稳地连起来。”

### 一二：空中灵活 / 修正型

被动 **「轻盈再跳」**：

- 保留一次二段跳；
- 二段跳力度为基础跳跃约 92%；
- 空中拾取小幸福的反馈更强，可额外增加少量“空中连击”表现，但不无限刷新二段跳。

玩家感受：

> “我可以在空中修正路线，走更灵活的高路。”

### 公平性约束

- 两个角色都能获得 9 张照片；
- 所有主线跳跃以布布为最低可达基准；
- 不允许一二直接用二段跳跳过整段核心机关；
- 不允许布布因为缺少二段跳无法完成某张照片。

# 5. V2 关卡结构规范

## 5.1 推荐地图尺寸

从当前：

> 120 × 12 tile = 5760 × 576px

调整为建议基线：

> **192 × 16 tile = 9216 × 768px**

原因：

1. 水平长度增加，但仍适合 H5；
2. 16 格高能容纳真正的上 / 中 / 下路线；
3. 相机 960×540 不会一次看完整个垂直区域，探索感更强；
4. 8 个 1152px 左右的关卡模块可清晰组织节奏。

如希望严格控制工作量，可先在第二关 V2 垂直切片中只做 4 个模块，验证系统后再扩展。

## 5.2 每关统一内容预算

- 8 个主模块；
- 20 个小幸福；
- 3 张照片；
- 8–10 个 Perfect 落点；
- 3 个检查点；
- 4 次以上路线分叉；
- 3–4 类主题机关；
- 最后 1 个“演出段”，不再介绍新规则。

## 5.3 小幸福分布原则

- 主路提供约 12–14 个；
- 奖励路线补足到 18–20；
- 20/20 代表本关路线掌握度，不要求在安全路线也能拿满；
- 任意两次必要 Combo 事件之间，按目标路线速度测算，不应出现无意义的大空档；

- 恢复 1 心（最多 3）；

- 形成短时间出现的幸福轨迹；

# 9. 收集、徽章与复玩系统

## 9.1 明确“小幸福”的定位

V2 建议把小幸福定义为：

> **单局路线表现物，不是永久逐个收藏品。**

- 每次进关都会重新出现；
- 结算显示本次数量；
- 存档保存历史最高数量；
- 关卡选择界面写“最高小幸福 18/20”，不要写成永久收集进度。

真正永久收藏的是：

- 照片；
- 徽章；
- 纪念卡 / 合影。

这样既解决当前存档歧义，又适配路线选择与 Combo。

不建议只给 S/A/B/C 总评价。温馨项目更适合“缺哪个目标就补哪个”。

### 满载而归

本关单局小幸福 ≥ 18/20。

### 一路稳稳

本关无伤完成。

### 心流时刻

本关达到指定最大 Combo：

- 第一关建议 12；
- 第二关建议 15；
- 第三关建议 14。

最终阈值以测试结果调整。

- best happiness；
- best combo；
- best hearts / no-damage；
- best time；

## 12.1 不要继续直接维护压缩后的上传包

当前上传包只有构建产物：HTML / CSS / 压缩 JS / 地图 / 素材，没有清晰源代码结构。

## 12.3 LevelScene 的职责要收缩

当前 LevelScene 同时负责：

- 输入；
- 移动；
- UI；
- 物体生成；
- 伤害；
- 存档结果；
- 相机；
- 交互。

V2 应让 LevelScene 只做编排，核心规则进入 system / object。

## 12.4 移动平台正确实现

优先方案：

> 让 Arcade body 自己有速度，immovable + allowGravity(false)，到达边界后反向，并正确设置 friction。

若必须使用 Tween 控制位置，则启用 Phaser 对 Tween / drag 驱动物体提供的 direct control 能力，并保证 moving body 的速度 / delta 可被碰撞系统识别。

验收：

- 玩家站在水平平台中央 5 秒，不应明显相对滑移；
- 垂直平台上升时玩家不应抖入平台；
- 平台暂停 / 页面切后台恢复后位置不跳变。

## 12.5 动态障碍不要升级到 Matter Physics

本项目无需为了“旋转锤”等机关切 Matter。

使用 Arcade Physics 的简单形状 + 视觉动画即可：

- 锤子视觉旋转，伤害球体沿预设路径移动；
- 木马视觉圆周运动可近似成多平台错相上下移动；
- 纸箱用普通 dynamic body；
- 滑板用 moving platform 逻辑。

目标是稳定、可调、易测，而不是物理真实性。

- `unlockedLevel` → 原样；
- `selectedCharacter` → 原样；
- 不根据旧数据自动猜测 Combo 徽章；
- 版本迁移失败时要回退到安全默认值，但不要因为一个字段异常清空全部存档。

# 15. 音效、粒子与“爽感”预算

## 15.1 音效

当前程序化 oscillator 可以保留为 fallback，但 V2 最好增加非常轻量的短音效：

- 收集；
- Perfect；
- Combo 里程碑；
- 弹簧；
- 照片快门；
- 检查点；
- 受伤；
- 最终重逢。

收集音应根据 Combo 阶段升调，形成“越连越舒服”的听觉奖励。

## 15.2 粒子

Boot 阶段生成简单小星 / 圆点纹理即可，避免大量素材。

预算：

- 普通收集：4–8 粒；
- Perfect：10–16 粒；
- Combo 10：短尾迹；
- Combo 20：持续但低密度尾迹；
- 同屏活跃粒子建议设置上限。

## 15.3 屏幕抖动

仅用于：

- 受伤；
- 强弹簧；
- 高级 Perfect 里程碑。

不用于每次普通拾取。

提供 `reducedShake` 设置，并在结束时确保相机状态恢复。

# 16. 难度曲线与边界条件

## 16.1 关卡难度

第一关：

> 学会“看路线、落准”。

第二关：

> 学会“保持空中节奏”。

第三关：

> 学会“在时间窗口里执行路线”。

## 16.2 强制边界

- 任何主线机制必须先单独教学，再组合；
- 新机关第一次出现时不与伤害机关同时出现；
- 关键临时平台必须可重复触发；
- 单次失败不应造成超过一个检查点的损失；
- 主线上不设置“只能二段跳通过”的间距；
- 不依赖极端像素级跳跃；
- 不使用随机平台位置决定成败；
- 动态障碍节奏固定或可预测，视觉上必须给预警；
- 一次屏幕内最多突出 2 个需要精确判断的动态危险源。

# 17. V2.1：无限“今天也去见你”模式

此模式不作为 V2 首要目标，三关主线好玩之后再做。

## 17.1 模式结构

通关三关解锁。

不用真正程序随机生成 tilemap，而是：

> **手工制作 Chunk → 按规则随机拼接。**

每个 Chunk：

- 约 960–1440px 宽；
- 标注主题、难度、入口高度、出口高度、是否含弹簧 / 风 / 动态平台；
- 至少准备 18–24 个 Chunk 再上线，避免短期重复感。

## 17.2 生成约束

- 入口 / 出口必须兼容；
- 同一高压机制不能连续出现三次；
- 每 3–5 个 Chunk 插入一个舒缓段；
- 所有组合以布布可达为最低标准；
- 难度随距离只逐步提高，不突然翻倍。

## 17.3 结算

显示：

- 距离；
- 最高 Combo；
- Perfect 次数；
- 本次角色；
- 个人最佳。

这会成为长期复玩的主要模式，而 Campaign 继续承担剧情、照片与角色建立。

# 18. 数据埋点 / 调优接口

即使当前不联网，也建议先定义统一事件接口，以后接统计系统无需重写玩法。

事件至少包括：

- `level_start`
- `level_finish`
- `checkpoint_reached`
- `player_damage`（hazardKind）
- `player_fall`
- `combo_break`（reason / combo）
- `perfect_landing`
- `photo_challenge_start`
- `photo_challenge_success`
- `photo_challenge_fail`
- `route_branch_enter`
- `restart`
- `quit_level`

调优重点看：

1. 哪个 x 区域死亡 / 受伤集中；
2. 哪张照片几乎没人尝试；
3. 哪个角色完成率明显更高；
4. Combo 通常在哪些位置断；
5. 安全路与奖励路实际选择比例；
6. 玩家第一次通关后是否主动重玩。

# 22. 最终 V2 核心体验定义

改版完成后，玩家的一段典型体验应该是：

> 我看到前面有两条路。地面很好走，但上面有一串小幸福，于是我踩蹦床上去；第一个平台刚好落在中心，“Perfect！”；连着两个幸福后 Combo 到了 8；前面软锤正扫过来，我没有停下，而是借气球再弹一次；一二可以二段跳修正，布布则更容易稳稳落到小平台中心；我看到旁边闪着相机图标，于是拐进一个 10 秒挑战，连续踩完三个移动木马平台，拍到“旋转木马”；回到主路时 Combo 已断，但下一串幸福就在前面，我自然又想重新连起来。

此时，游戏已经不再是：

> “一直按右，然后偶尔跳。”

而是：

> **“我知道终点在哪，但我想把去见你的这段路走得更漂亮。”**

这应当成为《布布一二：去见你的小幸福》V2 所有设计与实现决策的最高判断标准。

# 附录 B：实现时最重要的 12 条不可退让规则

1. 不直接长期 patch 压缩后的 `index-*.js`；
2. Tiled 里存在的关键属性必须真的执行；
3. 关键开关失败后必须可重试；
4. 布布必须能完成全部主线和照片；
5. 一二不能用二段跳跳过整段设计；
6. 每关必须有自己的核心机制，不复制 97% 地形；
7. 小幸福是单局表现，照片才是永久收藏；
8. 普通障碍不再全部等价于“伤害矩形”；
9. 移动平台必须先修稳定，再用它设计关卡；
10. 触屏 `releaseAll()` 必须覆盖 canvas 外松手和失焦；
11. 高路线失败尽量回落到安全路线，而不是死亡；
12. 每加一个新机制，都要回答：“它是否让左/右/跳本身更有意思？”
